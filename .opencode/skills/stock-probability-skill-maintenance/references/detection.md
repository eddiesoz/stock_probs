## Skill candidate detection

Propose skill work only when current repository evidence shows at least one of these conditions:

- the same project-specific instruction is needed repeatedly and is not already covered;
- an admitted skill names a command, path, or behavior that no longer exists;
- a required workflow repeatedly fails because durable local guidance is missing; or
- the approved catalog, metadata, project skill index, references, and actual discovery disagree.

First search existing project skills and authoritative repository instructions. Prefer updating an
existing skill when its scope already covers the need. A dependency, framework, or upstream skill
existing elsewhere is not by itself evidence that Stock Probability needs another skill.

Record the candidate, repeated evidence, proposed owner, overlap check, and smallest useful scope.
Stop at the proposal unless the current task explicitly approves creation, update, or retirement.
Do not invoke infrastructure or state services, write observations automatically, or import an
upstream skill collection.
